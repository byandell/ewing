# Time & Temperature Design App (`tempApp`)

This document records the prompt, architectural design rationale, implementation details, and verification steps for refactoring the legacy `temp.design()` interactive temperature spline designer into a modern, web-safe Shiny application (`tempApp`) and Shinylive WebAssembly demo.

---

## Prompt

```text
Create a demo app from `temp.design()` in `R/temp.R`. This needs input of `mysim <- init.simulation()`. Set this up similar to `R/fivePlotApp.R`. Deploy as demo in similar fashion to `demos/fivePlotApp.qmd`. Document this prompt and process in `doc/refactor/time_temp.md`.
```

---

## Architectural Rationale

1. **Legacy Graphics Locator vs. Modern Reactive Shiny UI:**
   - The original `temp.design()` function in `R/temp.design.R` used base R's `graphics::locator()` in a modal loop to capture interactive mouse clicks. While functional in desktop R console sessions, `locator()` blocks the server event loop and cannot run in web environments or Shiny apps.
   - `tempApp()` replaces this with a reactive Shiny interface built on `bslib::page_sidebar`. Node moves are captured via `input$temp_click` and immediately updated in reactive state (`shiny::reactiveValues`).

2. **Dual Spline (High & Low Temperature) Management:**
   - In **ewing**, daily thermal fluctuation is specified by daily high and low cubic splines (`High` and `Low` elements of `community$temp`).
   - `tempApp()` allows users to switch between editing the High and Low temperature splines using radio buttons, maintaining separate node coordinate vectors for both curves.

3. **Degree-Day Integration (`activeTemp()`):**
   - Stage transition kinetics in the simulation depend on degree-days (DD). Any adjustment to high/low daily temperatures triggers `activeTemp(community)`, which integrates degree-days using `temp.repeat()` and `temp.spline()`.
   - `tempApp()` displays side-by-side plots:
     - **Left (`plot_temp`):** Interactive daily high (red) and low (blue) temperature splines with click-to-move node editing.
     - **Right (`plot_degreeday`):** Real-time degree-day accumulation curve generated by `temp.plot(community)`.

4. **Monotonicity Boundaries:**
   - Day knots ($X$) must remain strictly increasing ($x_1 < x_2 < \dots < x_n$) to allow valid cubic spline interpolation. Node moves on click are automatically constrained between neighboring knot boundaries ($x_{i-1} + 0.01 \le x_i \le x_{i+1} - 0.01$).

5. **Serverless Shinylive Deployment:**
   - `demos/tempApp.qmd` packages the R app logic along with standalone implementations of core `ewing` temperature functions (`getTemp`, `setTemp`, `temp.spline`, `temp.repeat`, `break.backSpline`, `activeTemp`, `temp.plot`). This allows the app to execute entirely in WebAssembly inside the user's browser without requiring a backend server process.

## Implementation Summary

### 1. R Package Function (`R/tempApp.R`)

- **Function Signature:** `tempApp(community = NULL, title = "Daily Temperature Design Explorer")`
- **Default Input:** If `community` is `NULL`, automatically initializes `mysim <- ewing::init.simulation(messages = FALSE)`.
- **UI:**
  - `bslib::page_sidebar` with modern light theme (`bs_theme(version = 5, ...)`).
  - Sidebar: Radio buttons for active curve ("High" / "Low"), coordinate text inputs (`x_coords`, `y_coords`), minimum temperature input (`min_temp`), and reset button.
  - Cards: Side-by-side plot cards for `plot_temp` (click handler `temp_click`) and `plot_degreeday` (`temp.plot()`), plus an instruction footer card.
- **Server:**
  - Reactive state management using `reactiveValues`.
  - Bidirectional synchronization between interactive plot clicks and text inputs.
  - Monotonicity checks and input validation (`length >= 3`, strictly increasing X).
  - Recalculates degree-day spline via `activeTemp(community)` on every valid modification.

### 2. Shinylive WebAssembly Demo (`demos/tempApp.qmd`)

- Quarto HTML document with `{shinylive-r}` code block (`standalone: true`, `viewerHeight: 750`).
- Embeds lightweight standalone temperature helper functions so the app runs self-contained in browser WebAssembly.
- Indexed in:
  - `demos/index.qmd` (added to listing contents grid).
  - `demos/_quarto.yml` (added `tempApp` to navbar left links).

### 3. Package Documentation & Export

- Added `@export tempApp` and roxygen documentation in `R/tempApp.R`.
- Generated `man/tempApp.Rd` and updated `NAMESPACE` via `devtools::document()`.
- Updated `inst/doc/time_temp.md` to document `tempApp()` and `demos/tempApp.qmd`.
